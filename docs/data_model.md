# Data model

Star schema in Postgres, split across two schemas: `staging` (raw landing
zone, 1:1 with the generator's CSVs) and `warehouse` (the modeled star
schema the SQL views and the dashboard read from). Full DDL:
[sql/01_schema.sql](../sql/01_schema.sql).

## Grain

| Table | One row = |
|---|---|
| `warehouse.fact_maintenance_event` | one failure / scheduled inspection / preventive replacement, on one component, on one aircraft |
| `warehouse.fact_flight_hours` | one aircraft's flight hours on one calendar day |

Getting the grain right up front is what makes every metric downstream
unambiguous -- see [metrics.md](metrics.md).

## Dimensions

- **dim_aircraft** -- tail number, type, manufacturer, in-service date, fleet status.
- **dim_component** -- ATA chapter, name, category, criticality, unit cost, and
  `hourly_downtime_cost` (used only by the cost metric, see metrics.md).
- **dim_base** -- maintenance base, region, country.
- **dim_date** -- day-grain calendar attributes, generated by the ETL to span
  exactly the date range present in the loaded data (not a fixed range).

## Facts

`fact_maintenance_event` has two Postgres `GENERATED ALWAYS AS ... STORED`
columns, computed by the database itself rather than by application code:

```sql
repair_hours  = EXTRACT(EPOCH FROM (repaired_at - failed_at)) / 3600.0
downtime_cost = labor_cost + parts_cost
```

A `CHECK (repaired_at >= failed_at)` constraint makes an invalid repair
window impossible to load in the first place, not just something the
Phase 3 quality checks would later catch.

`fact_flight_hours` is the MTBF denominator -- see metrics.md for why
operating hours, not calendar time, is the right unit.

## Simplifications (documented on purpose)

- Every aircraft carries all 15 component types continuously from its
  in-service date; there is no separate installation-history table. A
  fleet with partial retrofits or multi-engine redundancy per aircraft
  would need one.
- The ETL is a full-refresh batch load (`TRUNCATE` + `INSERT`), not
  incremental CDC -- the right complexity level for this project's data
  volume. See [src/fleet_reliability/etl.py](../src/fleet_reliability/etl.py).
